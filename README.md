# 非虚构图书创作与长篇协作

把长篇写作分为两条协同的轨道：**创作流**负责每一页读起来是否清楚、准确、有吸引力；**工作流**负责整本书能否跨章节、跨会话持续推进，并最终可靠合并。两条轨道共享同一份项目事实、术语、论点和文风约定。

本 skill 的写作取向受到 William Zinsser《On Writing Well / 写作法宝—非虚构写作指南》和 Steven Pinker《The Sense of Style / 风格感觉：21世纪写作指南》的启发。只采用高层次、通用的写作观念，形成原创流程；不要复现原书段落、例句、独特比喻、章节结构或大段总结，也不要冒充两位作者的文风。

## 何时使用

- 从一个主题、问题或核心创意发展成非虚构图书方案、目录和章节。
- 持续写作长篇中文书稿，需要在多次会话中记住设定、论证、证据、术语和未完成任务。
- 续写、编辑或合并经济、技术、社会学及交叉领域的书稿。

如果用户只要一篇短文、邮件或普通技术文档，不启用整书工作流；按请求完成即可。

## 两条协同轨道

### 创作流：把每一章写好

1. **先明确读者和承诺。** 写出目标读者、他们已有的知识、读完后应理解或重新思考什么。全书的核心创意用一句可检验的主张表达；避免只有主题、口号或宏大愿景。
2. **建立章节问题。** 每章回答一个具体问题，并推动全书主张。用“问题—答案—证据/场景—含义—过渡”组织材料，结构可随内容调整。
3. **从具体材料进入抽象观点。** 优先使用可核查的案例、人物行动、制度细节、数据或技术过程，再解释它说明什么。案例不能替代证据，也不能让一个故事承担总体结论。
4. **让句子容易理解。** 明确谁做了什么；优先使用具体、常用且含义准确的词；把重要动作放在动词里；拆开负担过重的句子；减少空洞名词化、套话、重复限定和无功能的转折。
5. **照顾读者的认知负担。** 新概念出现时给出短定义，并用后文例子落实；控制每段承担的任务；在必要处提醒论证走到哪一步。不要把熟悉领域的术语密度当成严谨。
6. **保持作者声音。** 采用符合题材与读者的直接、诚实、沉着语气。保留作者有意的节奏、幽默和判断；不要把全文磨成同一种短句，也不要添加虚假的个人体验或戏剧性。
7. **分层修订。** 先审主张、章节作用和论证顺序，再审段落推进、例证与过渡，最后修句子、用词、标点和重复。每轮只优先处理一种问题，避免局部润色掩盖结构缺陷。

### 工作流：让整本书持续生长并可合并

1. **先创建书稿项目骨架。** 在用户指定位置或当前项目目录中组织持久文件。项目至少包含：
   - `BOOK_BIBLE.md`：核心创意、读者、主张、范围、边界、作者声音、事实与假设。
   - `OUTLINE.md`：全书结构、每章问题、章节结论、关键材料、字数目标与状态。
   - `STYLE_GUIDE.md`：本书语言选择、术语、语气、格式和禁用写法。
   - `RESEARCH_LOG.md`：来源、出处、关键主张、引文/数据定位、核验状态与待查事项。
   - `CONTINUITY.md`：跨章事实、时间线、人物/机构、定义、承诺、前文伏笔与避免重复的内容。
   - `MANUSCRIPT/`：按稳定编号保存章节，例如 `01-introduction.md`、`02-...md`。
   - `SESSION_LOG.md`：每次工作记录完成项、修改文件、待办和下一步。
   不要为了形式创建空白占位文件；首次工作时填入已有信息，未知处明确标注待确认。
2. **将核心创意逐级展开。** 从一句主张和读者承诺，发展为全书论证地图，再到部/篇、章、节、场景或论据。每一级都说明它如何支撑核心主张。发现目录失衡、重复或缺乏材料时，先调整地图，不用凑字数掩盖问题。
3. **用小批次生成长稿。** 一次约定一个可审阅单元（通常是一节或一章的一部分），完成后更新目录状态、证据记录和连续性记录，再继续下一单元。用户要求一次性输出时遵照其要求，并说明本次覆盖范围；不要声称没有生成的部分已经完成。
4. **续写前恢复上下文。** 先读取书稿圣经、目录、风格指南、连续性记录、研究日志、会话日志和相关前后章节。确定上次停点、下一节目的、已用论据和不可擅改的决定，再开始续写。
5. **每个单元结束时做交接。** 记录实际写了什么、证据状态、需要用户决定的事项、与相邻章节的接口、下一步文件和目标。更新文件中的状态，不依赖聊天历史作为唯一记忆。
6. **文件分工清晰。** 每章只保留一个权威正文文件；避免把整书反复复制到多个总稿，减少版本漂移。若用户需要单一合稿，从已编号章节按目录顺序生成合并稿，并保留章节来源映射。
7. **合并前检查。** 核对目录顺序、标题层级、章节边界、重复段落、遗漏章节、术语和数字一致性、交叉引用、引文来源与各章节状态。合并后标记生成时间和输入文件清单；不要静默覆盖作者手工维护的总稿。
8. **按全书维度复核。** 定期检查主张是否被证据支持、各章是否重复、概念是否前后一致、论证是否有断档、案例是否有代表性限制、读者是否得到足够解释。优先修复会影响全书理解的问题。

## 学科适配与证据纪律

- **经济学：** 区分描述、因果推断、模型假设与政策判断。标明数据口径、时间范围、样本和不确定性；相关性不能写成因果。
- **技术：** 交代系统边界、工作机制、适用条件、失败模式和版本/时间信息。区分已部署事实、路线图、推测和营销主张。
- **社会学：** 交代概念定义、研究对象、方法、样本和情境。区分行动者观点、研究者解释与群体层面的结论；避免把个案写成普遍规律。
- **交叉主题：** 每个领域的概念首次出现时说明采用的定义；同一术语有多种含义时明确本书用法。
- 事实、数据、引文和可争议的专业主张应有可追溯来源。不要编造引文、文献、统计数据或研究结论。缺少来源时标注待核验，并向用户说明需要补证。
- 读者友好不能以删掉限制条件、样本边界或重要争议为代价。用通俗语言表达复杂内容，同时保留结论成立的条件。

## 输出与协作方式

- 先交付可审阅的书稿单元，不以写作建议代替用户要求的正文。
- 章节开始处可用简短内部说明列出本章任务、论点和证据需求；除非用户要看过程，不把这些生产说明混入面向读者的正文。
- 未经用户要求，不擅自改变核心主张、目标读者、章节结构、事实立场或已确认术语。发现冲突时指出具体位置，并提出最小可选修订。
- 字数目标是规划指标，不是灌水理由。未达到目标时，优先找出缺失的论证、例证、解释或反方观点。
- 当用户提供的材料不足以支持强结论时，收窄表述、标记不确定性或提出需要补充的证据，不用流畅措辞掩盖空白。

## 每次完成时的收尾

在项目文件允许时同步更新相关记录；结束回复简要说明：本次完成的书稿单元、更新的项目记录、待核实/待决定事项和推荐的下一单元。对于纯构思问答，不强制写入文件。
