# 证据、脚注、图表与 PDF 发布规范

## 1. 来源选择与核验

按主张类型选择来源，不按“看起来权威”排序：

| 主张 | 首选来源 | 可补充来源 | 不能单独承担的来源 |
| --- | --- | --- | --- |
| 定义、机制、技术规格 | 标准、官方文档、原始论文 | 权威媒体、教材 | 无署名博客、模型回答 |
| 数字、趋势、政策 | 官方统计、数据集、原始调查 | 权威媒体 | 未给口径的二手图表 |
| 研究结论 | 同行评审论文、工作论文原文 | Google Scholar 检索到的出版物 | Google Scholar 搜索页本身 |
| 事件与人物行动 | 一手声明、公开记录、权威媒体报道 | 多家独立媒体 | 转载链、匿名截图 |
| 百科背景 | Wikipedia 作为入口和术语线索 | 原始参考文献 | Wikipedia 作为争议性数据唯一来源 |

`SOURCE_REGISTER.json` 的 `status` 使用 `verified`、`pending`、`rejected`。`verified` 不是“永远正确”，而是已经核对作者、标题、日期、来源地址和主张定位；`pending` 必须阻止正式发布，但可以出现在研究草稿中。

## 2. 脚注和尾注

正文使用 Markdown 脚注标记，例如：

```markdown
模型能够生成解释，但解释不等于因果证据。[^SRC-003]
```

标记应紧跟被支持的事实或判断，不把一整段不同主张都挂在段尾。`CITATION_REGISTER.json` 至少记录：标记 ID、正文文件、行号或段落、对应来源 ID、具体定位、注释文本、注释类型和核验状态。PDF 可以采用页脚脚注或章末尾注，但转换后必须仍能从标记回到完整来源信息。

## 3. 图表与 ECharts

每张图至少保留三份文件：数据（CSV/JSON）、生成配置或脚本、最终静态资产（SVG/PNG/PDF）。`FIGURE_REGISTER.json` 将三者和来源 ID 绑定。ECharts 适合生成交互式预览；图书 PDF 必须使用可打印的静态输出，并在图注写明数据源、时间范围、单位、样本和必要的处理步骤。没有原始数据或可复现转换脚本的“AI 生成图表”不得进入正式版。

## 4. 完整图书 PDF 的最低生产要素

- 封面：书名、副标题、作者/版本信息，且封面文字可提取或在资产清单中登记。
- 扉页：书名、作者/版本、日期。
- 版权/版本页：首版日期、资料核验状态、必要的免责声明。
- 目录：与实际章节标题和顺序一致。
- 正文：章节边界、统一标题层级、页眉/页脚、连续页码。
- 图表：编号、图题、来源注、字体和替代文本。
- 注释与参考文献：所有正文标记均能回溯到完整条目。
- 技术质量：PDF 可打开、中文字体嵌入、无空白异常页、元数据完整。

这些要素由 `BOOK_PACKAGE.json` 声明，并由 `scripts/check_book_package.py` 在最终交付前检查。
